## 1. Executive summary

Tabellarium's comment base is unusually dense (51 % of production lines, 31 % of test lines) and, atypically for that density, **carries far more knowledge than dead weight**. The mechanical debt classes are near zero: no TODO/FIXME anywhere, no commented-out code, no ceremonial `@param x the x` blocks, no separator banners, no change chronicles at file heads. Preconditions are consistently carried by `require`/`check` with named messages rather than prose; invariants that matter (probe-gap CAS, exactly-once diversion claim, clock-anchored sentinel) are backed by dedicated tests; the 125 test-rationale blocks follow one documented pattern. The center of gravity of the remaining debt is therefore not ceremony but **drift in the safeguard-free zone**: the documentation run does not check references (`failOnWarning` unset), and precisely there the audit found the gravest items — a metric-inventory KDoc table that contradicts the code it sits on (finding 1, the one Critical), a public-interface contract line describing a call-site that does not exist anymore (finding 2), a README breaker default that is wrong by a factor of three (finding 3, cross-check), two dangling symbol references and one placeholder link (findings 5, 6, 13), and ten bare references to per-report analysis finding IDs that will ambiguate as the report chain grows (finding 4). The second, smaller cluster is **concept duplication instead of hub-and-spoke**: the "never block the Kafka I/O thread" rationale exists in ~6 places, the "shared byte arrays are read-only by convention" contract in 5, with no canonical location that the copies could defer to.

**Conclusion**

1. **State:** predominantly knowledge, little dead weight. The debt's center of gravity is *unchecked drift* (references and mirrored facts that no tool guards) plus *scattered why-knowledge that is canonicalized nowhere* — not redundancy with the code. The share that can silently become wrong is structurally large — effectively **every** symbolic reference (392 occurrences) and every mirrored fact (metric tables, default values, cross-class concept copies) — but the share that *has* already become wrong is small (3 broken references, 2 wrong fact mirrors found).
2. **Reducibility and limiting factor:** low as a percentage, and that is the correct outcome. Lossless condensation potential is in the low single digits of comment lines (mainly the 5× read-only-arrays repetition and the 2× dispatcher worker-death text). Decompositions are barely applicable — the large blocks are class-level KDoc, already at their canonical location, and the in-method comments are almost all location-bound. The limiting factors are (a) the missing checked documentation run — without `failOnWarning`, symbolic references cannot be considered safeguarded, so relocating prose into references *increases* risk today — and (b) the missing canonical anchors (no ADRs, no package KDoc, no prefix vocabulary) that passes 2–3 would need.
3. **Most essential risks & anomalies:**
   - The Critical drift sits in the **metrics contract** (finding 1) — the exact place operators read when building dashboards; the correct numbers exist in `./README.md` and `./docs/metrics/`, so the KDoc is the odd one out.
   - **Do not touch in any hygiene pass:** the only-copy why-knowledge blocks that pass every test here — `HalfOpenThrottle`'s clock-anchored sentinel rationale (`./src/main/kotlin/eu/inqudium/tabellarium/HalfOpenThrottle.kt:69`), `MessageEnricher`'s key-bound rationale (`…/MessageEnricher.kt:167`), the `ignoreExceptions` rationale (`…/ResilientMessageSender.kt:309`), the incident chronicle in `…/LogstashHttpMethodKeyValueIngestTest.kt:22`. They are long, correct, actionable, and irreplaceable; every one names its failure mode. They are explicit non-findings.
   - Ten comments cite analysis-report finding IDs (`H-1`, `M-6`, …) whose numbering scheme restarts with every report in `./docs/assessment/` — currently still resolvable, structurally guaranteed to collide (finding 4).

## 2. Scope & methodology

See the metadata block for the include/exclude lists, the test-code decision, and the public/internal boundary. Method: Phase 1 collected the mechanical inventory (density, block sizes, TODO/ceremony/duplication greps, reference extraction, churn) and ranked the files; Phase 2 read every production file completely and every score-3+ test file completely, applying the four-axis carrier test per non-trivial comment; score-1/2 test files were skimmed for fixture KDoc and pattern conformance. Phase 3 killed false positives against the convention sources and the public-API boundary. Known limitations: (a) churn/`git blame` age indicators are void — the whole history spans ~34 hours; (b) no Dokka run was executed, so the count of *machine-detected* unresolved references is a manual lower bound, not a tool result; (c) `./README.md` and `./docs/` were only cross-checked where in-code comments point at them, not audited in full — the two contradictions found suggest a separate docs-vs-code pass would pay off. Existing prefix vocabulary: none documented; emergent `Note:`/`CAUTION:` only. The documentation run checks no references (Dokka `failOnWarning` unset). Test rationale blocks: 125 occurrences of the "What is to be tested?" pattern (counting basis: `rg -c` per file).

## 6. Systemic patterns

1. **Unchecked symbolic references (the enabling condition for half of all findings).** 392 `[Symbol]` occurrences in `./src/main/kotlin/` (counting basis: `rg -o "\[[A-Za-z][A-Za-z0-9_.]*\]"`), checked by no build step: Dokka runs on demand only and without `failOnWarning`. Three broken instances found by manual reading (findings 5, 6, 13) — a lower bound, not a census. Representative locations: `./src/main/kotlin/eu/inqudium/tabellarium/ResilientMessageSender.kt:41`, `…/KafkaAppenderMetricsBinding.kt:68`, `…/ProducerRegistry.kt:197`. Until the documentation run turns red on unresolved links, every relocation of prose into references (the direction most findings here recommend) *adds* risk instead of removing it — which is why the guardrail is pass-0 in section 7.
2. **Mirrored facts without a single source.** The same authoritative fact is maintained in code *and* restated numerically/tabularly in prose: metric inventory + cardinality (code enums vs. KDoc table vs. README table — KDoc wrong, finding 1), breaker defaults (code vs. README vs. config guide — README wrong, finding 3), the XML surface (setters vs. KDoc example vs. README table vs. config guide — KDoc/README incomplete, finding 8). ~5 mirror clusters (counting basis: cross-checks performed during Phase 2). The two confirmed drifts both sit in the mirror, never in the code-adjacent original — the predictable failure mode of unowned copies.
3. **Concept rationale duplicated at every touchpoint instead of hub-and-spoke.** The "never block the Kafka I/O thread → fallback must be queue-decoupled" rationale appears in ~6 places (`FallbackDispatcher` class KDoc — the natural canon —, `ResilientMessageSender` KDoc ##Fallback and ##Threading plus two inline comments, `KafkaAppender` KDoc; counting basis: `rg "I/O thread"` + reading); the read-only-arrays contract 5× (finding 7); "null fallback = operator's explicit drop choice" 4×. Each copy is individually correct today; the risk is scattering, not wrongness. Resolution direction: one canonical block per concept (existing class KDoc or pass-2 package KDoc), one-line pointers elsewhere — with the *locality-beats-reference* caveat respected for the two sites per concept where the information is load-bearing at the line.

**Positive counter-pattern (recorded for balance, not a finding):** the mechanically detectable debt classes are at or near zero across the whole repo — 0 TODO/FIXME, 0 commented-out code blocks, 0 ceremonial `@param` docs, 0 file-head change histories; preconditions ride in `require`/`check` with named messages; the four documented-then-verified only-copy rationale blocks (listed in the executive summary) all name their failure mode, which is exactly the form this audit exists to protect.
