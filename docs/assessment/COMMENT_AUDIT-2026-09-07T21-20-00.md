## 1. Executive summary

The comment base of tabellarium is a knowledge carrier first and a cost factor second, and the first audit's remediation holds: the mechanically detectable debt classes are at zero (no commented-out code, no `TODO`, no ceremonial `@param`, no `@param` without a parameter, no unresolved KDoc link - the last now guaranteed by Dokka's `failOnWarning`), the prefix vocabulary of ADR-0001 is in use (27 prefixed statements in production code), and the documentation-contract test added today turned the most drift-prone mirror of the first audit - the operator guide's defaults table - into a checked one. What this round found sits, as before, in the one place tooling cannot reach: **prose that resolves but no longer tells the truth.** The single Critical is a KDoc sentence in the circuit-breaker configuration that still sends operators to a "per-class override path" which the linked symbol's own KDoc, ADR-0002 and the guide (since today) all deny - the link is green, the claim is false. The High is a reference habit that regressed under today's remediation pressure: seven comments cite analysis reports by date only ("the 2026-09-07 analysis"), on a day that produced four different reports, whereas the first audit had established naming the immutable file. The Mediums are the expected shape for a codebase this carefully written: one concept paragraph sitting in a function body instead of a KDoc, one 41-line field KDoc that carries its cost derivation next to its decision, one metric-inventory mirror kept by instruction rather than by test, and one documentation duplication that today's dispatcher-skeleton extraction created (three identical `@param` blocks). The Lows are condensations - a JDK specification restated, an exception list the code keeps, in-file "above/below" pointers - each in the low single digits of lines, plus one clause written today that already names removed code (the "restart path" in the breaker-name KDoc, two hours after ADR-0004 removed it). Comment density is 1.31 in production and 0.56 in tests; that ratio is the product of the convention, not a symptom, and no quota is proposed.

**Conclusion.**

1. **State:** knowledge, not dead weight. The center of gravity of the remaining debt is *semantic drift under green tooling* - a resolvable link with a false sentence, a date that names four reports, a mirror kept by "must be updated together" - plus a small amount of derivation-at-the-code. Roughly 5-6 % of the production comment lines can silently become wrong: the unchecked mirrors (metric inventory KDoc, the numbers restated in the breaker KDoc), the date-only references, and the in-file relative pointers; everything symbolic is now safeguarded.
2. **Reducibility and limiting factor:** condensation potential is ~3 % of production comment lines (about 75 of 2 658: the VT-cost derivation, the ignored-exceptions enumeration, the `.properties` specification, the duplicated `@param` blocks, the metric table); decomposition (finding 3) changes the line count by roughly zero because the target KDoc does not exist yet. The limiting factor is not missing canonical locations any more - ADRs, the guide's canonical table and the report files exist - but that the remaining why-knowledge is genuinely indispensable and correctly placed: a reduction beyond ~3 % would remove rationale, not redundancy.
3. **Most essential risks & anomalies:**
   - 🔴 `ResilientMessageSender.kt:375-376` promises an operator override that does not exist - the only comment in the module that actively misleads, and it survived three remediation cycles because its link resolves.
   - 🟠 Seven date-only report references (four in production, three in tests), all written today; the reference convention the first audit established (name the file) was not applied to the new reports.
   - 📚🔴 stock that must not be touched in any hygiene pass: the `MetricsBindings` own-binder rationale (`:23-47`), the `MessageEnricher` key-bounding why-not (`:171-201`), the `inAppend` VT decision (`KafkaAppender.kt:289-295` - decision and rejected alternative, not the derivation), the `BoundedWorkerDispatcher` close-phase invariant (`:44-51`), the `LogstashHttpMethodKeyValueIngestTest` incident chronicle - each is the only copy of a failure mode.
   - Persisting pattern from the first audit: the "never block the Kafka I/O thread" rationale is still stated at six touchpoints instead of one hub with pointers.
